## Le site

Site **multi-pages** : un dossier par thématique (`site/<page>/index.html` + `site/<page>/<page>.js`), ressources communes dans `site/shared/`.

```
site/
├─ index.html            page principale de l'artifact : redirige vers accueil/index.html (ni doctype ni <head> : l'outil Artifact les ajoute)
├─ shared/style.css      tout le CSS (thèmes clair/sombre, BD, menu)
├─ shared/common.js      menu sandwich, lien actif, BD du mode tutoriel, stockage local (window.PCR.store)
├─ shared/dialogues.js   GÉNÉRÉ depuis docs/dialogues.md : ne pas éditer
├─ attaque_ransomware/ premières actions en cas de rançongiciel (8 actions, guide ANSSI) + BD de la leçon 9 ; menu « 09 Attaque par rançongiciel »
├─ qui-contacter/      page d'urgence hors parcours (pas de BD, pas de leçon), lien « SOS » en tête du menu
└─ accueil/ notions/ menaces/ contextes/ practilio/ sensibilisation/ ia/ reglementation/ incident/ assurance/ acteurs/ prestataires/ outils/ sources/
```

- Chaque page : document HTML complet (doctype, `<body data-page="<id>">`), une seule `<section class="view">`, puis les scripts `../shared/dialogues.js`, `../shared/common.js`, `<id>.js`. Accueil : encadré « Avant de commencer » (Practilio fictive, projet pédagogique EPITA) puis **deux chemins** et rien d'autre : 1) urgence → bouton « Qui contacter » → page dédiée `qui-contacter/` (uniquement le sélecteur structure × situation, réponse affichée d'emblée et recalculée à chaque choix ; logique dans `qui-contacter.js`, retirée de la page Incident qui renvoie vers elle), 2) sensibilisation complète → `notions/index.html`. Pas de BD sur l'accueil (attribut `data-no-tuto` sur la section ; `data-tuto-anchor` permet ailleurs de choisir où insérer la BD). Le reste de l'ancien accueil (liste des leçons, formulaire « structure + rôle », « Pourquoi Practilio », « Notre démarche ») est mis de côté dans [docs/accueil-contenu-retire.html](docs/accueil-contenu-retire.html), à reporter sur une autre page ; `accueil.js` garde la logique du formulaire mais ne fait rien tant que le formulaire est absent, `sensibilisation.js` (onglets + quiz), `reglementation.js` (questionnaire), `qui-contacter.js` (sélecteur « qui contacter ») ; les autres pages n'ont pas de logique propre.
- Liens internes : toujours `../<page>/index.html` (jamais `#page`, jamais `../<page>/` sans `index.html`, pour fonctionner en local, sur l'artifact et chez un hébergeur).
- **En-tête (bandeau fictif + menu) et pied de page : source unique [docs/layout.html](docs/layout.html)**, recopiée entre les marqueurs `<!-- LAYOUT:HEADER -->` / `<!-- LAYOUT:FOOTER -->` de chaque page par `python3 docs/sync_layout.py`. Ne jamais modifier ces blocs directement dans une page.
- **Dialogues BD : source unique [docs/dialogues.md](docs/dialogues.md)** → `python3 docs/build_dialogues.py` (écrit `site/shared/dialogues.js`). Les dialogues ne contiennent que des faits déjà vérifiés et présents sur la page.
- Menu sandwich à gauche (`#menu-btn`, panneau `#drawer` avec `nav#nav`) : liens de haut en bas, groupés (Comprendre / Practilio / Se former / S'orienter / Ressources), numérotés dans l'ordre des leçons. Le lien actif est calculé par `common.js` d'après `data-page`.
- Mode tutoriel : planche BD (personnages SVG originaux `TOON`, `buildComic()` dans `common.js`), bulles révélées au clic, navigation leçon précédente/suivante ; bouton `#tuto-toggle` (classe `tuto-off`, mémorisé en localStorage).
- **Ajouter une page** : créer `site/<id>/index.html` + `<id>.js` (copier une page existante), ajouter le lien dans `docs/layout.html` puis `sync_layout.py`, ajouter la leçon dans `docs/dialogues.md` puis `build_dialogues.py`, ajouter `<id>` à `PAGES` dans `docs/build_dialogues.py`, mettre à jour [docs/parcours-utilisateur.md](docs/parcours-utilisateur.md).
- Publication via l'outil **Artifact** : https://claude.ai/artifact/7zijhaG621JNWKrSgJ6CEu (privé par défaut ; l'utilisateur le partage lui-même). Republier avec `file_path` = `site/index.html`, `root` = le dossier `site`, et `files` listant **tous** les fichiers des sous-dossiers (chemin publié = chemin relatif à `site/`). Vérification visuelle possible en local : `firefox --headless --no-remote --profile <dossier vide du scratchpad> --screenshot sortie.png file://…/site/<page>/index.html`.

## Contraintes du sujet à ne jamais casser

- **Bandeau visible sur chaque page** : « projet pédagogique EPITA, Practilio est une entreprise fictive ». Coordonnées Practilio fictives : `securite@practilio.example` ; téléphone `08 36 65 65 65` (choisi par l'utilisateur), harmonisé sur `qui-contacter/` et `practilio/` (étape « Signaler un incident à Practilio »).
- Page « Qui contacter » : style voulu par l'utilisateur = verbes d'action simples (« Prévenir… », « Contacter… », « Effectuer une notification… »), sans détails techniques ; pas de « niveau », pas de mention « (fictif) ».
- **Aucun logo ni charte graphique d'organisme réel** (ANSSI, CNIL…) : citer + lien uniquement.
- **Chaque acteur, prestataire, éditeur, texte cité doit exister et être vérifié** ; une référence inventée ou un lien mort est plus sanctionné qu'une absence. Vérifier par WebSearch + `curl` (un 403/429 = protection anti-bot, pas un lien mort). Ne pas attribuer de qualification ANSSI (PASSI/PRIS/PDIS) à un prestataire nommé sans vérification sur la liste officielle.
- Minimums : 3 contextes, 3 profils, 5 acteurs (dont ≥ 2 santé), 5 prestataires, 5 catégories d'outils de ≥ 3 éléments dont une OT santé, au moins un scénario transposé des situations Practilio (coffre de mots de passe, blog marketing, module de facturation « Rebirth », VPN vers centrale de fluides médicaux), un contrôle de compréhension par profil.
- Textes dont l'application est en cours : **indiquer la date de consultation**.
